## Contract implementation layering
Even in one class, isolate logic into testable concepts: input normalization; publisher/participant authentication; source policy and version binding; revision request state; nondeterministic source retrieval and consensus; immutable offer/escrow allocations; refund/exit/maturity closure; value accounting; bounded read indexes; external message tracing and read-only verification.

**Implementation order is critical:** canonical deterministic state/permissions -> economically safe deposit/credit/claim invariant -> independent source verification and semantic consensus -> UI adapters -> live integration. Writing a glossy frontend first conceals unproved custody assumptions.

## Mandatory package/check scripts
Suggested `package.json` scripts (must actually implement): `dev`, `build`, `lint`, `typecheck`, `test`, `test:e2e`, `network:check`, `cli`, `preflight`. `preflight` chains network check, typecheck, lint, unit tests and production build. Add Direct Mode in CI as separate Python job, never fake it with `pytest` mock-only substitutions. Pin local CLI exact and verify with `./node_modules/.bin/genlayer --version`. Do not use `npx` if it would download a nonpinned CLI from network.

## Security pipeline
Require jobs for `npm ci`, network check, TS typecheck, ESLint, Vitest, Next build, production-only dependency audit, Direct Mode actual contract tests, model/semantic-snapshot tests, economic simulator/invariants, any supported mutation checks, Playwright desktop/mobile and docs/deployment consistency. Set protected default branch required checks. Avoid committing build output/cache/node_modules/private env files.

## Current compatibility note
The attached Patchbound example used CLI `0.39.1` and `genlayer-js 1.1.8`; that prior source is a format example, not proof those two packages support every API exposed by the 2026-10-13 GenLayer documentation. Codex must inspect the *installed pinned release*, compile and call the actual ABI and verify the target network response. If production support requires a CLI other than user-authorized `0.39.1`, stop with evidence and ask for permission instead of breaking the network/toolchain constraint.
