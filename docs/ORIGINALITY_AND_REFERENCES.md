# Clean-Room Originality and Reviewed References

## Engineering references, NOT implementation templates
- [Crossbench](https://github.com/zoefunds/Crossbench): two-sided evidence dispute and staked judgment. Some failed consensus escrow-recovery patterns identified in its repo. Do not clone its case/claimant/jury vocabulary, escrow symmetry, ranking logic, UI or disputed party flow.
- [Vowmark](https://github.com/Bibidee/vowmark): versioned public commitment bond, separated Registry/Vault, retries and custody handling. Do not clone commitment/maturity board, issuer-remedy relationship, public promise bond or UX.
- [Accordant](https://github.com/Bibidee/accordant): immutable criterion-bound delivery agreement and publisher/requester funded GEN escrow, signed GitHub evidence, closure and challenge flows. Do not clone deliverable/milestone criterion judgment, task acceptance, lemon/yellow frontend or exact contract methods.
- Patchbound sample handoff: bilateral GitHub code-patch acceptance. Used only as *handoff packaging and verification-process example*, not contract code or app product design.

## Revigate distinct identity
What matters: identity-continuous **rulebook version**, materiality, acknowledgments, a program cohort, pre-agreed future cash entitlement and participant opt-out under changing rules. Materiality is the validator question; project deliverable completion is NOT evaluated.

## Hostile similarity gate
Review product problem, wallet roles, economic model, semantic question, states, evidence input, routes, page layout, visual identity, class/method naming, prompts and README wording. If a reviewer can plausibly call it 'Accordant with rulebook text' or 'Vowmark with a beneficiary', stop and redesign the offending flow. Generic safety concepts are allowed: immutable terms, role authorization, bounded evidence, consensus, finality, accounting invariants, adversarial tests.
